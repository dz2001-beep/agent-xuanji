# Code Review 技能

当用户请求审阅代码（"review"、"审阅"、"看看这段代码"、"代码有什么问题"等）时，遵循以下流程：

## 步骤

1. **通读代码**：先完整读取待审阅文件（用 fs.read_file 或 shell.run 获取内容），理解整体结构与意图。
2. **逐项排查**，按以下维度检查：
   - 正确性（correctness）：越界、空值、竞态、边界条件、off-by-one、类型误用
   - 安全性（security）：注入、路径穿越、敏感信息泄露、危险命令
   - 性能（performance）：不必要的重复计算、同步阻塞、O(n²) 模式
   - 可维护性（maintainability）：命名、重复代码、复杂度、注释
   - 风格（style）：格式不一致、未使用的变量、console.log 残留
3. **输出格式**：按严重程度分三级，每级给出 行号 / 问题 / 建议修复：

   ```
   ### 🔴 严重（会导致错误或安全问题）
   - L12: `total += i` 在 `i <= 10` 时多算一次 —— 建议改为 `i < 10`

   ### 🟡 中等（边界情况或潜在缺陷）
   - L30: 未处理 `input` 为 null 的情况

   ### 🟢 轻微（风格/可维护性）
   - L5: 变量名 `x` 含义不明 —— 建议改为 `itemCount`
   ```

4. **总结**：最后用 2-3 句话总结代码整体质量与最需要优先修复的 1-2 个问题。
